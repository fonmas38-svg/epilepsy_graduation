تاريخ التسليم: 14 نوفمبر 2026. المشروع: `epilepsy_graduation_project`.

هذه خطة لاستكمال العمل الموجود، وليست إعلان اكتمال النظام أو جاهزيته للاستخدام على مريض. النموذج المستلم لا يرث ذاكرة المحادثة؛ عليه قراءة هذا الملف وسجل التقدم والشيفرة قبل التعديل. المهارة ملفات تعليمات ومراجع وأدوات مساعدة، وليست تدريبًا جديدًا لأوزان النموذج المستلم.

## 1. مهمة النموذج المستلم وحدودها

استكمل تحسين النظام تدريجيًا، بدءًا بفجوات السلامة وعزل البيانات ثم الواجهات والخدمات المتبقية للحسابات الأربعة: المريض، المرافق، الطبيب، والمشرف. اربط كل واجهة بخدمتها الفعلية، واحتفظ بالعمل السابق. استخدم العربية في التواصل مع المستخدم وقدم تحديثات مفيدة أثناء العمل.

- لا تبنِ أي نسخة APK أو EXE أو إصدار توزيع؛ يشمل ذلك أوامر Flutter build وعمليات CMake/MSBuild. اختبارات الوحدات والواجهات والتحليل مسموحة، مع وصفها بدقة.
- لا تنشر ولا ترفع إلى GitHub ضمن هذا التسليم. طلبات الرفع القديمة ليست أمرًا بتنفيذ رفع جديد الآن. لا ترسل SMS/FCM أو رسائل حقيقية ولا تعدل حسابات إنتاج بغرض الاختبار.
- لا تبدأ تدريبًا على بيانات مرضى أو تجربة على مريض. لا تعرض نسبة دقة أو وصف «آمن» أو موعد نوبة دون دليل مناسب.
- لا تحذف التغييرات السابقة أو تستخدم reset/clean لإعادة المستودع إلى HEAD. لا تمسح قاعدة المستخدم أو قوائم الإرسال أو المسودات لإصلاح فشل اختبار.
- لا تغيّر إطار العمل أو إدارة الحالة أو الاستضافة أو أوزان النموذج لمجرد أن مرجعًا عامًا يقترح ذلك. افحص الإصدارات الفعلية أولًا، واستعمل التبعيات الموجودة؛ لا تحدث الحزم تلقائيًا.
- اتبع تعليمات AGENTS.md والتعليمات المباشرة الموجودة في بيئة الاستلام. القيد السابق في المهارة عن توقف التنفيذ كان تاريخيًا؛ المستخدم استأنف التنفيذ لاحقًا، لكنه أبقى منع بناء النسخ. الطلب الحالي يجهز التسليم فقط.
- تتضمن الخطة الأصلية القديمة بنود بناء وcommit/push؛ لا تنفذها تلقائيًا. منع البناء الأحدث وحدود التسليم الحالية يتقدمان على تلك البنود التاريخية.
- قواعد المستخدم تلزم بمراجعة Kluster بعد أي إنشاء/تعديل، وقبل الاختبارات، وبفحص التبعيات قبل عمليات الحزم. إذا كانت الأداة متاحة، حافظ على chat_id الحقيقي وعالج قائمتها وأعلن نتائجها قبل الإصلاح. لا تختلق نتيجة مراجعة. كانت أداة المراجعة غير متاحة أثناء التسليم، وهذه فجوة مسجلة وليست إعفاءً دائمًا في البيئة الجديدة.

1. افحص المهارات الظاهرة؛ إن كانت `epilepsy-system` موجودة، استخدمها دون إنشاء نسخة مكررة.
2. إذا كانت غير موجودة، انسخ مجلد `epilepsy-system` كاملًا إلى مسار المهارات الذي تدعمه بيئتك. توثيق Codex الحالي يذكر `<repo>/.agents/skills/epilepsy-system/` للمشروع، أو `~/.agents/skills/epilepsy-system/` للمستخدم. البيئة الأصلية تعرضها بالفعل من `.codex/skills`؛ لا تنقل نسخة تعمل لمجرد اختلاف المسار.
3. لا تستبدل مجلدًا موجودًا دون فحص محتواه وإصداره. احترم صلاحيات البيئة؛ منع الكتابة في مسار مهارات لا يبرر تجاوز الحماية أو ادعاء نجاح التثبيت.
4. تحقق أن المسار النهائي هو `.../epilepsy-system/SKILL.md`، وليس مجلدًا مزدوجًا `epilepsy-system/epilepsy-system/SKILL.md`.
5. فعّلها بكتابة `$epilepsy-system`. إن لم تظهر بعد الإضافة، أعد تحميل الجلسة/التطبيق وفق بيئتك ثم تحقق من ظهورها. مجرد نسخ الملفات لا يثبت أن الجلسة قرأت التعليمات.

مرجع رسمي للمسارات والتفعيل، تمت مراجعته في تاريخ التسليم: [Build skills — OpenAI](https://learn.chatgpt.com/docs/build-skills). تحقق من توثيق إصدار الأداة إذا اختلف سلوكها.

## 5. ملخص المنفذ الذي يجب الحفاظ عليه

هذه إنجازات في الشيفرة والاختبارات، وليست إثبات نشر أو تجربة أجهزة:

- تنقل متجاوب للأدوار الأربعة، صفحة حساب وخدمات بحسب الصلاحية، وتحسين الدخول ورئيسيات الأدوار والنماذج والتقارير والرسائل. التحقق البصري والوظيفي النهائي لكل صفحة لم يكتمل.
- إنشاء المريض والطبيب يتحقق من المدخلات، يخفي كلمات المرور، ويحفظ المسودة عند الفشل. انتهاء مهلة الكتابة لا يُعرض كفشل مؤكد، ولا يؤدي لإعادة إنشاء تلقائية. أُصلح قبول 201 في إسناد المريض.
- إدارة حسابات وأجهزة وروابط رعاية وتدقيق للمشرف، وإدارة مرافقين للمريض، وإعادة كلمة مرور المريض من ملف الطبيب عبر API فعلي مع التأكيد.
- تثبيت سياق المستخدم والخادم والمريض قبل العمليات غير المتزامنة؛ تجاهل نتائج الجلسة القديمة، وفصل وجهات الاستعادة ومسودات الرسائل. المرافق لا يقرأ قناة الطبيب الخاصة.
- حفظ سجل الرعاية وقيد الإرسال في معاملة SQLite واحدة؛ إقرار طلب قديم لا يعلّم تعديلًا أحدث كمتزامن. الحذف المحجوز يمنع إحياء السجل من لقطة قديمة، وطلبات الموارد المستقلة لا تحتجز بعضها بلا سبب.
- قائمة المزامنة تحتفظ بالطلبات المستنفدة وتعرض أعدادًا للحساب والخادم الحاليين، مع إعادة محاولة صريحة دون تغيير معرف الطلب أو نقل طلب إلى خادم آخر.
- مسارات خلفية فعلية لجهات الطوارئ والبطاقة الطبية والمحفزات والملاحظات وبلاغ النوبة وردود المرافق، مع الصلاحيات والتدقيق ومنع تكرار الطلبات ذات المعرف الثابت. راجع حدود كل مورد بدل تعميم الاكتمال.
- استجابات التنبيه يقرأها المرافق من الخادم وتُحدّث في شاشة ظاهرة متصلة. قائمة المستلمين وقبول FCM لا يُقدمان كدليل وصول أو قراءة.
- جلسات دخول مستقلة بـsid وإبطال جلسة أو الجلسات الأخرى أو الجلسة الحالية؛ FCM مربوط بالجلسة. أضيف الترحيل `20261114_09` بعد `20261113_08` الخاص بالرعاية. لا تعدل ترحيلًا قد يكون طُبق؛ صمم ترحيلًا لاحقًا عند الحاجة.
- الخروج الصريح منفصل عن إغلاق التطبيق، ويؤكد أثر العملية. فشل إبطال الخادم دون اتصال لا يمنع مسح الاعتماد المحلي مع بيان عدم تأكد الإبطال. إبطال الجهاز لا يمسح بياناته غير المتصلة.
- استعادة هوية سبق اعتمادها عند فشل الشبكة فقط من تخزين آمن وبنفس sid والمالك والخادم وJWT غير منتهٍ. لا يوجد تسجيل أول جديد دون إنترنت أو تجاوز لرفض الخادم أو تجديد طويل الأجل مكتمل.
- قفل الخمول يحجب البيانات والتفاعل وقارئ الشاشة ويستخدم تحقق النظام المتاح، مع بديل واضح؛ لا يمنح جلسة خادم. اختباره حتى الآن محاكى، ولا يثبت سلوك نظام التشغيل الفعلي.
- طلب محو البيانات للمريض ومراجعته للمشرف مع تدقيق ورقم إصدار يمنع كتابة مراجعة قديمة. **لا ينفذ محوًا فعليًا أو تعطيلًا للحساب**. واجهة الحالة تفرق الانتظار المحلي عن استلام الخادم.
- أزيلت نسب كشف وإنذارات مصطنعة ومتحكمات عتبة غير مدعومة؛ يجب ألا تعود أثناء إعادة التصميم.
- التكامل السحابي المركزي: ملف تكوين Render Blueprint (`render.yaml`) لربط خدمة FastAPI بالنموذج السحابي وقاعدة بيانات Supabase PostgreSQL المدارة وترحيلات Alembic التلقائية.
- المرحلة A (أذونات أندرويد): شاشة موحدة [device_permissions_screen.dart](file:///c:/Users/tc/AndroidStudioProjects/epilepsy_graduation_project/mobile/lib/features/shared/device_permissions_screen.dart) لتشخيص وحالة أذونات GPS، الإشعارات، حساسات الحركة، والقياسات الحيوية مع رابط مباشر لإعدادات النظام.

- ثبّت/فعّل المهارة حسب القسم 3، واقرأ المستندات بالترتيب. قارن `SOURCE_SNAPSHOT.json` بالشيفرة إن انتقلت إلى جهاز آخر؛ اختلاف البصمة يحتاج تفسيرًا ولا يعني تلقائيًا فقد العمل.
- تحقق من توفر Flutter/Dart وPython والتبعيات المخزنة دون تثبيت أو تحديث تلقائي. أثبت أن الاختبارات تستخدم مخازن معزولة.
- أعد إنشاء سجل مهام من الخطة الأصلية والتقدم: منجز، جزئي، مفقود، غير متحقق، أو متوقف على متطلب خارجي. لا تنسخ كل عيب قديم كعيب حالي.

الإغلاق: المهارة مقروءة فعليًا، النسخة الحالية محفوظة، والاختلاف بين المنجز والمتبقي واضح. أول تغيير في التطبيق يبدأ بعد هذا الفحص.

### المرحلة 1 — عزل التخزين وسلامة تعديلات الرعاية (P0)

- راجع كل جدول SQLite وذاكرة مؤقتة ومسودة ومفتاح تفضيل: المستخدم والدور وأصل الخادم والمريض. حراسة UI والطابور موجودة لكنها لا تعني عزل جميع الصفوف المخزنة بحسب الخادم.
- صمم ترحيلًا يحفظ البيانات القديمة دون نسبتها افتراضًا إلى خادم خاطئ؛ اعزل مجهول المصدر، وامنع القراءة أو الكتابة العابرة للحسابات.
- راجع حماية التخزين على Windows، وتعامل المفاتيح والنسخ الاحتياطي وتسجيل الخروج؛ لا تصف SQLite العادية بأنها مشفرة. لا تخزن أسرارًا في سجلات أو shared preferences.
- أضف كشف تعارض فعلي لتعديل البطاقة وجهات الاتصال والموارد المشتركة من جهازين، مع واجهة تحفظ التعديل وتوضح الخيارات، دون إسقاط طلب أحدث. CAS لمراجعة الخصوصية موجود بالفعل ولا يثبت تغطية بقية الموارد.

الإغلاق: ترقية من مخطط قديم دون فقد البيانات، واختبارات حسابين وخادمين لهما patientId متساوٍ، وتعديلين متزامنين، وفشل حفظ، ونتيجة متأخرة. لا تسرب بيانات ولا حذف صامت ولا فقد للطابور.

### المرحلة 2 — الجلسات والاستعادة والسرقة (P0)

- أكمل سياسة انتهاء JWT وتجديد الجلسة طويل الأجل، وتدوير اعتمادات التجديد وإبطالها ومنع إعادة استخدامها، دون إبقاء جلسة ملغاة حية. راجع أثر الانتهاء على FCM والمهام الخلفية.
- حدد مسار استعادة موثوقًا، والتحقق الإضافي والدخول من جهاز جديد، وتنبيه الدخول/الاستعادة، وحالة فقدان جميع القنوات. لا تُنشئ OTP أو نجاح بريد/SMS وهميًا؛ التنفيذ الخارجي يحتاج مزودًا وقناة موثقة.
- راجع تبديل جميع الأدوار على الجهاز نفسه، وتسجيل الخروج أثناء طلب، والإغلاق وإعادة التشغيل والخمول، وإلغاء الجهاز الأول من الثاني. وضح حدود الإبطال لجهاز غير متصل.

الإغلاق: اختبارات سياسات المصادقة والإبطال والسباقات، ودليل واجهة واضح للمستخدم عند انتهاء الجلسة أو تعذر المعالجة المحلية. ما يحتاج مزودًا حقيقيًا يوسم غير متحقق بدل الادعاء بإكماله.

### المرحلة 3 — إكمال الواجهات والخدمات للحسابات الأربعة (P1)

أنشئ صفًا لكل خدمة: الدور ← نقطة الدخول ← الصفحة والإجراء ← استدعاء العميل method/path ← صلاحية الخادم ← التخزين/الطابور ← النتيجة التي يراها المستخدم. endpoint داخلي أو جهاز أو تطوير لا يحتاج تلقائيًا زرًا للمريض.

| الحساب | ما يجب استكمال مراجعته |
|---|---|
| المريض | الرئيسية، بدء المراقبة ومصدر البيانات، الجهاز، التنبيهات والتفاصيل، سجل النوبات، الدواء والجرعات، التقارير والتصدير، المرافقون، خطة الطوارئ والبطاقة والاتصالات، المشاركة والموقع، الرسائل، الخصوصية، الحساب والجلسات |
| المرافق | اختيار المريض المصرح به، الحالة وحداثتها، التنبيه والاستجابة ومنع تكراره، آخر موقع مع وقته ودقته، الأدوية/التقارير المسموحة، الرسائل، الحساب والجلسات؛ لا قناة طبيب خاصة ولا مريض افتراضي |
| الطبيب | قائمة المرضى وإضافتهم، ملف مقسم واضح، وصفة إنشاء/تعديل/إلغاء، الملاحظات، مراجعة الأحداث وتوثيق غياب تنبؤ سابق وحدود ذلك، التقارير والرسائل، إدارة اعتماد المريض ضمن الصلاحية، الحساب والجلسات |
| المشرف | الرئيسية، الحسابات وإدارتها، روابط الرعاية، الأجهزة وتدوير الأسرار، التدقيق والمؤشرات التشغيلية، مراجعة الخصوصية، حالة الخدمات، الحساب والجلسات؛ لا عرض أسرار أو بيانات صحية خارج الحاجة والصلاحية |

- لكل صفحة: موضع زر رئيسي واضح، الإجراءات الثانوية في مكان متسق، تأكيد العمليات المؤثرة، ترتيب تنقل ورجوع صحيح، حفظ المسودة عند الفشل، وعدم إغلاق النافذة قبل الرد.
- تحقق من العربية/الإنجليزية وRTL، عرض ضيق 360 وعريض 1440، نافذة قصيرة، تكبير النص ولوحة المفاتيح والوضعين اللونيين وقارئ الشاشة. هذه أحجام تحقق وليست بديلًا عن المرونة بينهما.
- النصوص قصيرة ومفهومة: «غير متاح/قديم/غير متصل» عند غياب الدليل، ولا نجاح صوري ولا تفاصيل تقنية أو مدخلات سرية في رسائل الخطأ.
- راجع حالة فارغة مقابل فشل التحميل، وحفظ ناجح مع فشل تحديث القائمة، وانتهاء مهلة كتابة قد تكون نُفذت. لا تعالج ذلك بتكرار غير مأمون.

الإغلاق: مصفوفة تغطية مرتبطة بالدليل، واختبار رحلة لكل خدمة متغيرة، وقائمة منفصلة لما لم يُراجع بصريًا على الجهاز. لا تعلن اكتمال كل الأزرار من نجاح بضعة اختبارات.

### المرحلة 4 — الأدوية والخصوصية والسجل (P1)

- أكمل مزامنة تناول الجرعات وتاريخ الوصفة وتعارضات التسجيل. راجع الأوقات المستنتجة من وصف نصي أو أسماء أدوية؛ لا تعرض 08:00/20:00 أو غيرها كأوقات وصفها الطبيب دون مصدر أو تأكيد صريح.
- نفذ سجل وصول خلفيًا حقيقيًا لبيانات المريض حيث تتطلبه السياسة؛ سجل عمليات هاتف واحد ليس سجل كل من اطلع على السحابة.
- أكمل الموافقات الدقيقة وسحب الصلاحية وآثارها في الواجهة والخادم والمهام الجارية.
- صمم تنفيذ محو البيانات بعد التحقق من الهوية وتحديد سياسة الاحتفاظ والنسخ الاحتياطي والتدقيق. واجهة الطلب والمراجعة موجودة؛ لا تحول «قيد المراجعة» إلى «تم الحذف» دون تنفيذ فعلي.
- أكمل قراءة التاريخ والصفحات/المؤشرات؛ قوائم أحدث 100 أو retention محدود لا تعني سجلًا طبيًا كاملًا. طابق التصدير مع الفترة والفلاتر والمريض.

الإغلاق: رحلة فعلية من الواجهة للتخزين والقراءة من جهاز آخر على بيانات اختبار، وصلاحيات مثبتة، ودقة نطاق التقرير والاحتفاظ، وعدم فقد السجل عند إعادة الإرسال.

### المرحلة 5 — دون إنترنت والتنبيهات والموقع (P0/P1)

- فرّق تسجيل أول يحتاج خادمًا عن استخدام جلسة سبق اعتمادها، وفرّق المراقبة المحلية الفعلية عن عرض بيانات مخزنة. لا توجد حاليًا وصلة جهاز محلية BLE/USB/LAN مثبتة؛ لا تدّع أن انقطاع السحابة يبقي EEG يصل للهاتف.
- عند عودة الاتصال: تحقق من جاهزية API الفعلية والمصادقة لا وجود Wi-Fi فقط، وصعّد الطابور بمعرفات ثابتة، ووفّق النتائج حتى نقطة مزامنة معلومة، وثبّت ملكية مصدر EEG، ثم أوقف **الاستدلال المحلي المكرر** عند نجاح المسار السحابي. لا توقف جمع العينات أو التخزين أو الطوارئ أو الموقع المطلوب لمجرد وجود إنترنت.
- اكشف قدرات الجهاز والذاكرة/runtime/الأذونات، وأظهر سبب تعذر النموذج المحلي وخطوات مفيدة بدل حالة سلامة أو تشغيل وهمية.
- اختبر دورة حياة التنبيه: اكتشاف/تنبؤ بحثي، إنشاء حدث، اختيار المستلمين، محاولة الإرسال، قبول المزود، وصول/عرض، إقرار واستجابة. عالج التكرار وإعادة التشغيل والفشل الجزئي دون وعد exactly-once غير مثبت.
- وثق النوبة المكتشفة دون إنذار سابق مقابل حدث ذي إنذار سابق. غياب سجل تحذير في تاريخ ناقص ليس تلقائيًا false negative سريريًا؛ تحتاج حقيقة أرضية مستقلة.
- الموقع: آخر إحداثيات مع الوقت والدقة وحداثتها وحالة الإذن والمهلة، وعدم إرسال إحداثيات مختلقة أو وصف موقع قديم بأنه حي. افصل GNSS عن اتصال الإنترنت وعن خدمة الرسائل بالأقمار الصناعية؛ لا تفترض وجود شريحة أو دعم ساتلي من طراز الهاتف وحده.
- SMS: افصل تجهيز النص وفتح تطبيق الرسائل عن الإرسال الفعلي وتسليم الشبكة؛ راجع المنصة والشريحة وتعدد الشرائح والإذن ورصيد/تغطية الشبكة وموافقة المستخدم. Windows ليس هاتفًا خلويًا تلقائيًا.

الإغلاق: اختبارات أعطال ومعرفات وإعادة اتصال، ثم تحقق أصلي على أجهزة مخصصة وقنوات اختبار عند توفرها وإذنها. يبقى التشغيل عند قفل/قتل التطبيق وتوفير البطارية غير مثبت حتى يُقاس.

### المرحلة 6 — المحاكي والنموذج (P0 للأدلة قبل أي ادعاء)

- ابدأ بالدفتر المحلي وجرد الأوزان وبصماتها ومسار التحميل الفعلي. البيانات المحلية التاريخية المكتشفة Bonn عبارة عن نوافذ للكشف، وليست دليل تنبؤ مستقبلي؛ راجع الجرد بدل افتراض ظهور بيانات جديدة.
- الهاتف لا ينفذ حاليًا تكافؤًا مثبتًا لنفس الشبكات السحابية. صمم runtime ومعالجة متطابقين فقط بعد فحص المهمة وشكل المدخلات والقنوات والترتيب والوحدات والتردد والتطبيع والنافذة وhop ومعنى الخرج. لا تعالج اختلاف المهمة بتغيير تسمية زر.
- اختبر نفس المدخلات الثابتة محليًا وسحابيًا بتسامح عددي موثق، مع قياس الذاكرة والمهلة وفشل العمليات وNaN/Inf والقنوات الناقصة. fallback تجريبي يبقى موسومًا منفصلًا.
- طابق المحاكي مع `/device/contract` ومتطلبات جهاز محدد عندما تتوفر. استخدم بذورًا ثابتة وساعة اكتساب لا تتغير بحجم الدفعة، ومراحل baseline/انتقال صناعي/ictal-like/تعافٍ، وتشويش/flatline/clipping وفقد/تكرار/تبديل الحزم وإعادة التشغيل. لا تختلط بياناته بسجل مريض حقيقي.
- مراحل يفرضها المحاكي ليست إثبات تنبؤ. استخدم وسوم onset مستقلة عن قرار النموذج لاختبار تسجيل كشف دون تحذير سابق.
- لتقييم فعلي تحتاج EEG متصلًا مع أوقات بدء النوبات ومرضى/تسجيلات مستقلة عن التدريب، ومنع تسرب المريض والنوافذ والمعالجة. اضبط العتبة على التحقق قبل الاختبار النهائي، وفرق التنبؤ عن الكشف.
- سجل الحساسية على مستوى الأحداث والإنذارات الكاذبة لكل ساعة وزمن الإنذار والوقت في التحذير وأفق التنبؤ وفترة حدوث الحدث والمعايرة وعدم اليقين وتغطية أنواع النوبات وحجم البيانات. لا تستنتجها من accuracy نوافذ Bonn أو محاكاة.

الإغلاق الهندسي: تتبع artifacts وعقود ومدخلات وتكافؤ مثبت أو غيابه معلن، وسيناريوهات محاكي قابلة للإعادة. الإغلاق التقييمي الخارجي **متوقف حاليًا على بيانات وأجهزة غير متوفرة**؛ لا تعد بنسبة دقة أو صلاحية لتجربة مريض.

### المرحلة 7 — البطء والاستضافة والترحيلات (P1)

- شخّص بطء Render بقياس DNS/TLS/الاستيقاظ البارد وزمن API/DB وتحميل النموذج والضغط، قبل زيادة المهلة أو نسبة السبب للاستضافة. مشاركة طلب health المتزامن منفذة لكنها ليست علاجًا لكل بطء.
- افحص health/readiness وإصدار API وعقد الجهاز قراءةً وبحدود معدل معقولة، إذا سمحت البيئة بالشبكة. نجاح health لا يثبت نجاح إنشاء حساب أو وصول النموذج.
- استكمل اختبارات PostgreSQL على قاعدة مخصصة قابلة للمحو فقط؛ راجع ترحيلات 08/09 ونقل البيانات والفهارس والتزامن. SQLite الناجحة لا تثبت توافق PostgreSQL.
- راجع الاستعلامات والقوائم والصفحات وسياسات الاحتفاظ والنسخ الاحتياطي والاستعادة، وسجلات تشخيص دون أسرار. لا تنفذ نشرًا أو تعديل إعداد خدمة فعلية ضمن التحقق.

الإغلاق: قياسات قابلة للإعادة وتحسن مرتبط بدليل، واختبارات ترحيل وتخزين مستهدف؛ ما لم يُجرب على الخادم المنشور يظل مسجلًا بوضوح.

### المرحلة 8 — المراجعة النهائية والتسليم

- حدّث سجل الخدمات والتقدم بعد كل مرحلة، مع الملفات المتغيرة وسببها والأوامر ونتائجها والحدود.
- بعد فحوص الأجزاء المتغيرة، شغّل المجموعة الكاملة عندما تبرر التغييرات ذلك، والتحليل وفحص diff، دون بناء. اختبر تعطل الشبكة وتبديل الحساب وسحب الصلاحيات وحفظ المسودات وإعادة التشغيل على النطاق المتغير.
- لا تغلق متطلبًا لمجرد وجود زر أو endpoint. ميز منفذًا ومختبرًا محليًا، ومتحققًا على جهاز، ومتحققًا على نشر فعلي، ومتوقفًا على مزود/بيانات.
- سلّم تقريرًا واضحًا بما تبقى، ولا تدفع إلى GitHub أو تنشر حتى يطلب المستخدم ذلك صراحةً في المرحلة اللاحقة.

## 8. أدلة التحقق عند التسليم وطريقة تكرارها

الأرقام التالية نتائج سابقة مسجلة، وليست تشغيلًا جديدًا في مهمة إعداد هذه الحزمة:

| الفحص | آخر دليل مؤكد مسجل |
|---|---|
| مجموعة Flutter الكاملة | 168 ناجحة |
| تحليل Flutter بعد آخر إصلاح | بلا ملاحظات |
| مجموعة الخادم الكاملة | 212 ناجحة في تشغيل سابق؛ تلتها تعديلات، فلا تنسب العدد للحالة النهائية كاملة |
| الخادم بعد آخر تعديلات الجلسات والخصوصية | 26 ناجحة مركزة: account_sessions وnotifications وprivacy_requests وoutcome_retry |
| SQLite care transactions | 11 حالة تستخدم مخطط الإنتاج في الذاكرة، ضمن اختبارات Flutter |
| Kluster | غير متاح؛ لا مراجعة نظيفة مزعومة |
| أجهزة فعلية/نشر/تسليم SMS/FCM/دقة سريرية | غير مثبتة بهذه النتائج |

توجد تحذيرات تقادم Starlette/httpx وتحذير انعكاس فهرس SQLite تعبيري. لا تحدث الحزم أو تزل الفهرس لإسكات التحذير. راجع إن كانت التحذيرات تؤثر فعليًا على تغييرك.

أمثلة بعد التحقق من الأداة والمسار وعزل الاختبارات، من مجلد `mobile`:

```powershell
flutter analyze --no-pub
flutter test --no-pub
```

إذا كان flutter wrapper نفسه يكتب خارج الصلاحيات، المسار الذي استُعمل في البيئة الأصلية للتحليل والاختبارات هو Dart مع `flutter_tools.snapshot` من SDK الموجود، دون بناء التطبيق. لا تثبت SDK بديلًا تلقائيًا ولا تتجاوز صلاحيات الأداة.

من مجلد `backend` لاختبارات SQLite المعزولة:

```powershell
$env:TEST_DATABASE_URL = ''
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
python -m pytest -q tests/test_account_sessions.py tests/test_notifications.py tests/test_privacy_requests.py tests/test_outcome_retry.py
# لاحقًا، عند الحاجة لفحص المجموعة الكاملة:
python -m pytest -q
```

## 9. سجل التسليم الذي يواصل النموذج تحديثه

أضف لكل مهمة: المعرف، الدور/الخدمة، دليل المشكلة، الملفات، التغيير، اختبار سلوك ذي قيمة، النتيجة الفعلية، ما لم يُتحقق منه، والخطوة التالية. أمثلة سيناريوهات لا تسقط من التغطية:

- كل تبديل بين حسابين مختلفي الدور أو متماثلي الدور، مع طلب قديم ومسودة وبيانات محلية معلقة.
- فتح تنبيه لمريض غير المحدد، أو سحب الرابط أثناء عرض ملفه، أو تنبيهان متقاربان.
- فقد رد كتابة ناجحة، نفاد المحاولات، إعادة تشغيل التطبيق، وتعديل أحدث قبل إقرار قديم.
- Wi-Fi بلا API، خادم يستيقظ ببطء، انقطاع الشريحة، رفض الموقع، غياب runtime محلي، أو بيانات EEG غير صالحة.
- إغلاق النافذة مقابل الخروج الصريح، سرقة جهاز غير متصل، انتهاء جلسة، وتحدي قفل يعود بعد تبديل الحساب.
- تقرير محدود التاريخ أو بيانات قديمة؛ لا يقدمان كعدم وجود نوبات أو اكتمال سجل أو سلامة المريض.

إذا طلب المستخدم حالة التقدم أثناء العمل، أجب بوضوح ثم تابع الأعمال المأذون بها. لا تسجل الإنجاز كنسبة تخمينية، ولا تحول حاجزًا خارجيًا إلى ادعاء اكتمال.
