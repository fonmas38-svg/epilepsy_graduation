الموجود محليًا: مجموعتان HDF5، كل منهما تحتوي 11,500 نافذة أحادية القناة بطول 262 عينة، وموسومتان بمهمة **كشف النوبة الجارية** باستخدام بيانات Bonn. لا توجد ملفات EDF متصلة في مجلد البحث. النسختان متطابقتان في SHA256؛ لا يجوز جمعهما على أنهما مرضى أو عينات اختبار مستقلة. التفاصيل والبصمات في [MODEL_ARTIFACT_AUDIT.json](MODEL_ARTIFACT_AUDIT.json).

تقرير CHB-MIT القديم يحتوي تناقضات حسابية: 188 حالة صحيحة من 200 تعطي حساسية 0.94 وليس 0.942؛ و177 من 200 تعطي 0.885 وليس 0.884. لم أحذف التقرير أو أنسب سبب هذه التناقضات إلى جهة محددة. أصبح API يعامله كتقرير غير موثق، ولا يعرض أرقامًا بديلة عند غيابه. عُثر على الدفتر `research/colab_seizure_detection.ipynb`: دالة B فيه تولد موجات صناعية، وكان يختار عتبة الدمج باستخدام مجموعة الاختبار. أُصلح الدفتر ومولده: وصف صريح للبيانات الصناعية، اختيار العتبة من التحقق، موازنة بالعينات دون مضاعفة أوزان الفئات، وتصدير التنبؤات والمجموعات وبصمات الأوزان. لم يُعَد تشغيل التدريب؛ لذلك لا تنطبق الإصلاحات بأثر رجعي على المقاييس السابقة. وجود الدفتر لا يثبت أن الأوزان الحالية صدرت من تشغيله تحديدًا دون سجل وبصمة مطابقين.

## عقد المحاكي الحالي

وُحّدت القيم الافتراضية لمحاكي الهاتف ومساري `/simulate/window` و`/simulate/stream` مع عقد الجهاز. رُفضت النوافذ الفارغة والطلبات التي تتجاوز الحدود.

`GET /device/contract` يعرض المواصفات الحالية: قناة EEG واحدة، ECG وحركة ونبض، 256 Hz، وحدات `normalized_demo`، دفعات حتى 512 عينة، ونافذة تجميع 262 عينة. هذه **مواصفات نموذج الاتصال البرمجي الحالي** وليست مواصفات جهاز طبي معتمد.

وُحّدت نافذة تجميع الجهاز إلى 262 عينة لتطابق الطول المعلن للأوزان الحالية. النوافذ الأخرى لا تُمدّد لتبدو متوافقة. قد يعمل مسار القواعد عند عدم توفر الشبكة، ويجب التحقق من حقل `engine` و`prediction_source`. هذا التطابق الشكلي لا يثبت تطابق توزيع الإشارة أو المعالجة مع التدريب الفعلي؛ يلزم التحقق منهما قبل توصيل جهاز.

```powershell
python partners/hardware-sim/sim_client.py --pattern stable --seed 42 --batch-size 32
python partners/hardware-sim/sim_client.py --pattern flatline --seed 42
python partners/hardware-sim/sim_client.py --pattern mains_noise --seed 42
python partners/hardware-sim/sim_client.py --pattern clipping --seed 42
```

الفاصل الافتراضي يساوي حجم الدفعة / 256؛ سرعة الشبكة والاستدلال تؤثر في زمن الوصول الفعلي. الإشارة ذات تردد عينات محدد، لكن المحاكي ليس جهاز اكتساب في الزمن الحقيقي. السعات صناعية؛ ليست ميكروفولت معايرًا، ولا تمثل نوبة مريض حقيقي.

## الحصول على تقييم قابل للمراجعة من كولاب أو كاجل

لا يلزم تنزيل كامل EEG كخطوة أولى. احتفظ بالنموذج مجمدًا، وصدّر:

1. ملف التدريب/Notebook المستخدم فعليًا، إصدار البيانات، سجل التنفيذ، ومعالجة الإشارة.
2. ملف NPZ يحوي `y`, `score`, `group` للاختبار و`val_y`, `val_score`, `val_group` للتحقق، و`train_group` لمعرفات مجموعات التدريب. استخدم معرفات بحثية غير تعريفية. درجات هذه المجموعات يجب أن تأتي من الأوزان المجمدة نفسها.
3. ملف JSON فيه `dataset`, `dataset_version`, `task`, `preprocessing`, `channel_names`, `fs`؛ أضف الوحدات ومدة النافذة والمرجع وتفاصيل الاستبعاد.
4. ملف الأوزان نفسه أو بصمته للمطابقة مع الخادم.

```bash
python research/scripts/evaluate_holdout.py \
  --predictions heldout_scores.npz \
  --weights frozen_model.pt \
  --metadata experiment.json \
  --group-kind patient \
  --min-specificity 0.95 \
  --output evaluation_bundle.json
```

اختيار 0.95 هنا سياسة بحثية قابلة للتغيير على التحقق، وليس معيارًا سريريًا معتمدًا. إذا كانت البيانات Bonn المعاد تجميعها، فاستخدم `--group-kind recording`؛ معرف التسجيل لا يثبت هوية المريض. لا تستعمل معرفات تسجيل مختلفة للشخص نفسه كأنها مرضى مستقلون.

التقرير يحسب الحساسية والنوعية والقيمة التنبؤية الإيجابية وROC-AUC وAverage Precision وBrier Score، ويستخدم bootstrap بالمجموعات عند توفرها. الأداة تتحقق من المدخلات المقدمة، ولا تستطيع إثبات صدق أصلها أو غياب إعادة استخدام الاختبار أثناء تطوير النموذج. لا تمنح علامة اعتماد تلقائية.

للتنبؤ المسبق فعليًا، نحتاج أيضًا تسجيلات اختبار زمنية متصلة، أوقات النوبات، فترات عدم التسجيل، تعريف أفق التنبؤ وفترة وقوع النوبة، وسياسة دمج الإنذارات وفترة منع التكرار. عندها تقاس حساسية الأحداث، الإنذارات الكاذبة/ساعة، وقت البقاء في التحذير، ومهلة الإنذار مع حدود عدم اليقين. دقة النوافذ وحدها لا تجيب هذه الأسئلة.

## ما يبقى قبل تجربة مريض

تحديد الجهاز والأقطاب والمونتاج والمرجع والوحدات ودقة التحويل والمعايرة ومعدل العينات، ثم اختبار جودة الإشارة وفقد العينات والتوقيت والبطارية. يلزم تقييم مستقل على نفس عقد الإدخال والسكان المستهدفين، ومراجعة مختص أعصاب وبروتوكول مناسب وموافقات لازمة للتجربة المقصودة؛ لا يعتمد المريض على النظام لتغيير علاج أو استبعاد نوبة.

مسار EDF ما زال يستخدم ترشيحًا غير سببي على مستوى التسجيل، ولا يجمع التعليقات الزمنية عبر حدود ملفات التسجيل. لذلك لا يمثل تقييمًا مستقبليًا حيًا، حتى بعد إصلاح التطبيع والتقسيم. لا تزال مطابقة معالجة التدريب مع الاستدلال، تجميع أحداث الإنذار، واختبار الجهاز الفعلي أعمالًا مطلوبة. لم أستبدل هذه المتطلبات بادعاء «أعلى دقة».

المراجع: [مبادئ FDA/IMDRF للتعلم الآلي للأجهزة الطبية](https://www.fda.gov/medical-devices/artificial-intelligence-enabled-medical-devices/good-machine-learning-practice-medical-device-development-guiding-principles)، و[توثيق CHB-MIT وملاحظة هوية chb01/chb21 ومواصفات التسجيل](https://physionet.org/content/chbmit/1.0.0/).
