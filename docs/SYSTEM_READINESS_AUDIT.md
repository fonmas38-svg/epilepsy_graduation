## 2) التدقيق التفصيلي لكل مكوّن

### 2.1 الباك-إند (FastAPI Backend)

* **نقاط النهاية والمسارات (API Routes):**
  - المصادقة وإدارة الجلسات (`POST /auth/token`, `POST /auth/login`, `GET /auth/me`).
  - استقبال بيانات أجهزة الرأس وتجميع النوافذ (`POST /device/ingest`, `GET /device/status/{patient_id}`).
  - إدارة الحسابات وإسناد المرضى للأطباء (`/accounts/users`, `/accounts/assignments`).
  - التنبيهات وضمانات التسليم (`POST /cloud/sync`, `/alerts`).
  - الفحص التشغيلي والمقاييس (`GET /health`, `GET /model/info`, `GET /model/metrics`).
* **قاعدة البيانات والترحيلات:**
  - يعتمد نظام ترحيل تلقائي عبر Alembic (`alembic upgrade head`).
  - يدعم العمل المحلي الخفيف عبر SQLite، مع وجود سكربت جاهز للترحيل إلى PostgreSQL/Supabase (`migrate_sqlite_to_postgres.py`).
* **نتائج التحقق التجريبي:**
  - فحص الإقلاع `startup_check.py`:
    ```
    STARTUP OK: {'classifier': True, 'device_hub': True, 'database': True}
    SHUTDOWN OK
    ```
  - مجموعة الاختبارات الآلية `pytest backend/tests`:
    ```
    96 passed, 1 warning in 150.11s (100% pass rate)
    ```

### 2.2 تطبيق الهاتف (Flutter Mobile App)

* **الأدوار المدعومة:**
  - **المريض (Patient):** شاشة الحالة اللحظية، طلب الاستغاثة SOS، إدارة الأدوية والجرعات، سجل الأحداث والتقويم، خطة الطوارئ الطبية بدون اتصال، إدارة أجهزة الإشارة، وإعدادات الحساسية.
  - **الأسرة/المرافق (Caregiver):** قائمة المرضى المرتبطين، شاشة الاستجابة للتنبيه وتنسيق الحركة، موقع المريض، وتوثيق تفاصيل النوبة.
  - **الطبيب (Doctor):** فرز المرضى حسب الحاجة للانتباه (Triage Sorting)، فحص ملف المريض والملاحظات السريرية، ومراجعة وتصنيف دقة التنبيهات (Adjudication).
* **البنية التحتية والتعريب:**
  - جدول نصوص موحد بـ 404 مفاتيح معربة بالكامل (`AppLocalizations`) مع دعم RTL كامل.
  - لا توجد أي نصوص عربية مضمنة داخل شاشات العرض (Zero hardcoded Arabic in screens).
  - نظام ألوان وسمة موحدة تدعم أمان عمى الألوان (Color + Icon + Text).
  - العمل دون اتصال عبر SQLite المحلي ونمط الطابور الصادر (Outbox pattern).
* **نتائج التحقق:**
  ```bash
  flutter analyze -> No issues found! (0 errors, 0 warnings)
  flutter test    -> All tests passed!
  ```

### 2.3 لوحة مدير النظام (Admin Dashboard)

* **الوظائف المنفذة:**
  - تسجيل الدخول الموحد بـ JWT وحماية المسارات حسب الدور (`ProtectedRoute`).
  - إنشاء وإدارة الحسابات لجميع الأدوار (طبيب، مريض، مدير).
  - إسناد المرضى للأطباء وإلغاء الإسناد (Assignments).
  - تفعيل وتعطيل الحسابات وإعادة تعيين كلمات المرور.
  - سجل تدقيق العمليات الحساسة (Audit Log).
* **نتائج التحقق:**
  ```bash
  npm run build -> ✓ built in 1.49s (dist generated successfully)
  ```

### 2.4 محاكي جهاز الرأس (Hardware Simulator)

* **الموقع:** `partners/hardware-sim/sim_client.py`.
* **الخصائص التشغيلية:**
  - برنامج عميل (Client) مستقل لا يفتح خادم ويب ولا يتعارض مع الخادم الرئيسي.
  - يحصل تلقائياً على توكن JWT من `POST /auth/token` ويرسل الدفعات إلى `POST /device/ingest`.
  - يولد إشارات فسيولوجية مترابطة (EEG + ECG + Motion + HR) بدون الحاجة لأي Dataset خارجية.
  - يدعم 4 أنماط رئيسية: `stable`, `watch`, `high_risk`, و `ramp` (نمط التدرج الزمني الذي يثبت قدرة النظام على التنبؤ المسبق وليس الكشف اللاحق).
* **نتائج التحقق:**
  ```bash
  python -m pytest partners/hardware-sim/test_sim_client.py
  -> 3 passed in 0.66s (100% pass rate)
  ```

## 3) مصفوفة الامتثال والحدود الصريحة (Transparency & Limitations)

لضمان الأمانة العلمية أمام لجنة المناقشة، يوضح الجدول التالي ما هو منفذ ومثبت وما هو معتمد على محاكاة:

| الخاصية / البند | الحالة الحالية | كيف يوثق في مشروع التخرج؟ |
|---|---|---|
| **تنبؤ ما قبل النوبة (Preictal Forecast)** | يعمل حالياً عبر معادلة استدلالية شفافة (`simulated_heuristic`) | يوضح في التقرير كمسار استدلالي شفاف يبرهن جاهزية المعمارية لاستقبال الأوزان العصبية المدربة. |
| **إشعارات الخلفية فوق شاشة القفل** | مدعومة عبر FCM وطابور محلي داخل التطبيق | يذكر أن التنبيه يعمل على الهواتف، وتفعيل الشاشة المقفلة بالكامل (Full-screen intent) يتطلب صلاحيات نظام أندرويد خاصة. |
| **بيانات أجهزة الرأس** | توليد رياضي فسيولوجي دقيق عبر المحاكي | يذكر صراحة أن النظام أُعد كنموذج أولي بدون عتاد فيزيائي (MVP without Hardware) والمحاكي يحل محل الجهاز. |
| **العمل بدون اتصال** | منفذ 100% عبر SQLite محلي لكل العمليات الحيوية | يعتبر من نقاط القوة الأساسية للنظام الطبي (Offline-first Resilience). |
