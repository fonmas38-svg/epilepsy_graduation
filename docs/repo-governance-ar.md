# حوكمة المستودع: حصر كل مساهم في مجلده

## المشكلة التي نحلّها

رفع أحد أعضاء الفريق ملفات في **جذر المستودع** (`main.py`, `simulator.py`,
`sensor_logic.py`, `requirements.txt`, `index.html`) عبر واجهة GitHub Web. هذه
الملفات تتعارض اسميًا مع نقطة تشغيل الخدمة الحقيقية (`backend/app/main.py`) ومع
`backend/requirements.txt`، وتظهر لأي قارئ كأنها نقطة انطلاق المشروع.

المطلوب: أن يرفع كل مساهم في **مجلده فقط**، ولا يستطيع لمس النواة.

## الحقيقة التقنية أولًا

> **GitHub لا يوفّر صلاحية كتابة على مستوى المجلد للمتعاونين على نفس المستودع.**

من يملك حق الدفع على فرع، يملكه على كل مسارات ذلك الفرع. لذلك الحل ليس «صلاحية
مجلد»، بل مزيج من أربع طبقات: **إزالة الكتابة + حماية الفرع + قاعدة مسارات +
فحص برمجي**. الطبقتان الأخيرتان منفّذتان في هذا المستودع بالفعل.

## الطبقات الأربع

| # | الطبقة | تمنع الدفع فعليًا؟ | أين تُضبط | الحالة |
|---|---|---|---|---|
| 1 | Fork + Pull Request (إزالة صلاحية الكتابة) | **نعم، 100%** | إعدادات GitHub | يدوي — عليك تنفيذه |
| 2 | حماية فرع `main` | نعم للدفع المباشر | إعدادات GitHub | يدوي — عليك تنفيذه |
| 3 | Ruleset: Restricted file paths | نعم (حسب الخطة) | إعدادات GitHub | يدوي — اختياري |
| 4 | `CODEOWNERS` + `path-guard.yml` | لا، لكن يوقف الدمج | داخل المستودع | ✅ منفّذ |

---

## الطبقة 1 — الحل الموصى به: Fork + Pull Request

هذا هو الحل الحقيقي لطلبك، ومجاني، ويعمل على المستودعات الخاصة والعامة.

1. `Settings` → `Collaborators and teams`.
2. أزل الزميل من قائمة المتعاونين (أو اخفض دوره إلى **Read**).
3. اطلب منه: `Fork` للمستودع → يعمل في نسخته → `Pull Request` إليك.
4. أنت تراجع وتدمج.

**النتيجة:** لا يستطيع الدفع إلى مستودعك إطلاقًا. حتى لو استخدم أدوات AI ورفع
50 ملفًا في الجذر، فذلك يحدث في *نسخته هو*، ولا يصل إليك إلا عبر PR تراجعه.

> ملاحظة: على المستودع **الخاص**، الـ Fork متاح فقط لمن له وصول قراءة. أبقِ دوره
> **Read** حتى يستطيع عمل fork وفتح PR.

## الطبقة 2 — حماية فرع `main`

`Settings` → `Branches` → `Add branch protection rule` على `main`:

- ✅ Require a pull request before merging
- ✅ Require approvals — عدد المراجعين: **1**
- ✅ Require review from Code Owners ← يفعّل ملف `.github/CODEOWNERS`
- ✅ Require status checks to pass → اختر `Path guard` و `Backend tests`
- ✅ Do not allow bypassing the above settings (طبّقها على المدراء أيضًا عند الجدية)
- ❌ Allow force pushes — اتركها معطّلة
- ❌ Allow deletions — اتركها معطّلة

## الطبقة 3 — Ruleset بقاعدة المسارات (اختياري)

أقرب شيء لطلبك الحرفي «امنعه من مجلدات أخرى» داخل نفس المستودع:

`Settings` → `Rules` → `Rulesets` → `New branch ruleset`:

1. **Target**: فرع `main` (أو `All branches` لتغطية كل الفروع).
2. **Bypass list**: أضف نفسك، حتى لا تعطّل عملك أنت.
3. فعّل **Restrict file paths** وأضف الأنماط الممنوعة:
   ```
   backend/**
   mobile/**
   admin-dashboard/**
   shared/**
   docs/**
   .github/**
   *
   ```
   النمط `*` وحده يغطي ملفات الجذر (بلا `/`).
4. فعّل أيضًا **Restrict file path length** و **Restrict file size** لمنع رفع
   ملفات ضخمة بالخطأ.

> **قيد مهم:** Rulesets بكامل قواعدها متاحة مجانًا للمستودعات **العامة**؛ على
> المستودعات **الخاصة** تحتاج GitHub Team أو Enterprise. تحقّق من خطتك، وإن لم
> تكن متاحة فالطبقة 1 تحقق الهدف نفسه بالكامل ومجانًا.

## الطبقة 4 — المنفّذة في المستودع

### `.github/CODEOWNERS`
كل المسارات مملوكة لك. مع تفعيل «Require review from Code Owners» في الطبقة 2،
لا يُدمج أي PR يمس النواة دون موافقتك.

عند إضافة الزميل رسميًا، فعّل السطر المعلّق فيه واستبدل `@teammate-username`
باسم مستخدمه الفعلي على GitHub.

### `.github/workflows/path-guard.yml`
فحص يعمل على كل PR ويفشل في ثلاث حالات:

1. **ملف جديد في جذر المستودع** — يسري على الجميع بلا استثناء. هذا وحده يمنع
   تكرار المشكلة الأصلية.
2. **مساهم محصور يعدّل خارج `partners/`** — يُفعّل بضبط متغير المستودع:
   `Settings` → `Secrets and variables` → `Actions` → `Variables` → `New variable`
   - Name: `RESTRICTED_AUTHORS`
   - Value: اسم مستخدم الزميل (أو عدة أسماء مفصولة بمسافات)
3. **أسرار أو نواتج بناء** — `google-services.json`, `serviceAccountKey.json`,
   `.env`, `node_modules/`, `build/`, `__pycache__/` … إلخ.

## ما يجب أن يُبلَّغ به الزميل

رسالة جاهزة للإرسال:

> العمل من الآن يكون في `partners/hardware-sim/` فقط. لا ترفع أي ملف في جذر
> المستودع — الفحص الآلي يرفض ذلك تلقائيًا. لا تعدّل `backend/` أو `mobile/` أو
> `admin-dashboard/`. اعمل على fork خاص بك وافتح Pull Request. المحاكي المعتمد في
> المشروع هو `backend/device_gateway_sim.py`، وعقد البيانات موثق في `docs/api.md`
> و`docs/hardware_integration.md` — أي محاكي جديد يجب أن يلتزم بهذا العقد ويكون
> **عميلًا** يرسل إلى الخادم القائم، لا خادم FastAPI ثانيًا.

## اختبار أن الحماية تعمل

1. اطلب منه فتح PR تجريبي يضيف ملفًا في الجذر → يجب أن يفشل `Path guard`.
2. اطلب منه فتح PR يعدّل ملفًا في `backend/` → يجب أن يفشل الفحص و/أو يُطلب
   موافقتك عبر CODEOWNERS.
3. اطلب منه فتح PR يعدّل `partners/hardware-sim/simulator.py` → يجب أن ينجح.

## ملاحظة على السجل التاريخي

الملفات التي رُفعت في الجذر سابقًا نُقلت إلى `partners/hardware-sim/` عبر
`git mv`، فبقي تاريخها محفوظًا. لم يُعد كتابة تاريخ Git ولم يُحذف أي عمل.
